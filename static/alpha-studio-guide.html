Posting to Alpha

Everything you need to get a post from your notes into a published Alpha article — the AI formatting step, what Studio requires before it'll let you publish, and the fixes for the two things people usually get stuck on.

Write your notes→ Format with the AI prompt→ Paste into Studio→ Add subtitle + image→ Publish
01Format your notes with the AI prompt first

This is the step that gets skipped most often. Studio's own upload box does not automatically format your text — if you paste raw notes straight in, that's exactly what comes out: raw notes. The prompt below does the formatting, and it has to run in a separate AI chat before Studio ever sees your text.

The prompt now tells the AI to put its whole reply inside a single code block, on purpose — a chat app would normally render a line starting with ## as an actual on-screen heading, and copying that rendered heading strips the ## characters (they were never actually displayed, only used to draw the heading). Text inside a code block is never re-rendered that way, so copying from it preserves the markers exactly.

  1. Open claude.ai (or whichever AI chat app you use) in another tab.
  2. Tap the 📋 Copy prompt button below, then paste it in as your message.
  3. Where it says [PASTE YOUR NOTES HERE], replace that line with your actual draft — bullet points, a rough paragraph, whatever you've got. Doesn't need to be tidy yet.
  4. Send it. The reply should come back entirely inside one code block — copy it using that code block's own copy icon, not manual text selection.
  5. Before pasting into Studio, delete the two ``` lines (one at the very top, one at the very bottom) — Studio doesn't want those, just the ## content itself.
The prompt 
You are helping me write an Alpha post for Growth Capital Group's investing education site. Take my notes/draft below and turn them into a clean, well-structured post using this exact plain-text format — no Markdown headers, no bold-as-headers, just these literal conventions:

FORMAT RULES
- Start every new section with a line that begins "## " (two hashes, one space).
- Right after "## " you can optionally add one bracket tag to set that section's style, then the heading text:
  - "## [TIP] Heading text" — a highlighted tip callout
  - "## [QUOTE] Heading text" — a pull-quote block
  - "## [TABLE] Heading text" — followed by a markdown table (see below)
  - "## [IMAGE] Heading text" or "## [IMAGE RIGHT] Heading text" — a placeholder for an image, layout left or right
  - "## Heading text" (no tag) — an ordinary section with a plain heading
- Two special one-off tags don't create a section — they set post metadata instead, and should each appear once, near the top:
  - "## [SUBTITLE] One-line subtitle here"
  - "## [SNIPPET] One or two sentence teaser/summary here"
- Within a section's body text you can use:
  - **bold**, _italic_, ++underline++
  - "- item" for a bullet list, "1. item" for a numbered list (one per line)
  - A real markdown table (header row, "---" separator row, data rows, pipe-delimited) — put it under a "## [TABLE]" heading, or just leave it bare and it'll still be detected as a table.
- Every "## " must be at the very start of its own line — don't let anything join lines together or strip the line breaks.
- Output your entire reply as plaintext inside a single code block (triple backticks), with nothing outside it. This is required — if the "## " lines render as normal text instead of staying inside a code block, your chat app will likely display them as actual headings, and I won't be able to copy the literal "## " characters back out. Do not format any part of the reply as real Markdown headings, bold, or lists outside the code block — the whole thing, including the "## " markers themselves, must stay literal text inside that one code block.

CONTENT RULES
- Educational/historical framing only — describe what a strategy or indicator would have done historically, never advice, predictions, or personalised recommendations.
- Keep my voice and facts — don't invent numbers, trades, or claims I didn't give you.
- Include a [SUBTITLE] and [SNIPPET] near the top, then organise the rest into logical ## sections (at least one heading, more if the content has natural sub-topics).

Here's my draft/notes to turn into a post:

[PASTE YOUR NOTES HERE]
This is a manual step, every time. Studio can't run the prompt for you yet — you run it in your own AI chat, then bring the finished text over. If a post you've published still reads unformatted, this is almost always why: either the raw notes went straight into Studio without a trip through the prompt first, or the AI ignored the code-block instruction and the ## markers got rendered away and lost on copy (see below for what to do if that happens).
02Bring it into Alpha Studio

Go to /alpha/studio (the "Studio" link in the nav, visible once you're set up as a partner).

  • Click the Paste Text tab in the upload panel (next to File and Link).
  • Paste in the AI's formatted reply — the whole thing, ## lines included.
  • Click Upload & Create Draft. It lands in your Drafts list below, ready to review.

You can also upload a Word doc, PDF, or Excel file directly, or paste a link — same Paste Text step still applies once you've got AI-formatted text ready to go, regardless of where the source material came from.

03Fill in what Studio requires before it'll publish

A draft can sit incomplete indefinitely — nothing goes live until you hit Publish, and Publish stays disabled until these three exist:

TitleThe headline — pulled from your formatted text, editable in Studio. Always double-check this before publishing.
SubtitleThe one-line hook shown under the headline. If your AI-formatted text included a ## [SUBTITLE] line, it's already filled in — otherwise add it in the Sub-title field.
Main imageUpload a file or paste an external image URL. One or the other, not both.

Need a heading partway through the body that wasn't in your original AI output? Use the + Sub-heading button in the editor — it drops a marker at your cursor and renders as a proper heading on the live page.

04Publish

Once the three fields above are filled in, the Publish button lights up. Published posts appear on your public Alpha page immediately and stay editable — edits to a published post don't need re-publishing, they go live on Save.

05Formatting tag reference

What each ## tag does, if you're editing formatted text by hand instead of re-running the prompt.

TagWhat it does
## Heading textPlain section heading — no tag needed for an ordinary section.
## [TIP] HeadingHighlighted tip callout box.
## [QUOTE] HeadingPull-quote block.
## [TABLE] HeadingFollowed by a pipe-delimited markdown table (header row, --- separator, data rows).
## [IMAGE] HeadingImage placeholder, left-aligned layout.
## [IMAGE RIGHT] HeadingSame, image on the right.
## [SUBTITLE] textSets the post subtitle — appears once, near the top, doesn't create a section.
## [SNIPPET] textSets the teaser/summary shown in post listings — also near the top, no section.

Inside a section's body text: **bold**, _italic_, ++underline++, - item for bullets, 1. item for numbered lists.

06Stuck on something else?
"My post looks like a wall of plain text." — almost always a copy problem, not a formatting problem: the ## markers were rendered as real headings in the AI chat, and copying that rendered text drops them. The prompt in Section 1 already tells the AI to reply inside one code block to prevent this — if it didn't do that, ask it directly: "Put your entire previous answer inside a single code block, unchanged, so none of it renders as markdown." Copy from that code block using its own copy icon, remove the two ``` lines, then paste into a fresh draft. (Skip suggestions like escaping hashes with backslashes or zero-width spaces — those change the actual characters and need extra cleanup or risk invisible characters breaking things; the code-block method is the reliable one.)
ChatGPT specifically ignores the code-block instruction. — it'll often reply with real rendered headings and bullets anyway. Use the same follow-up as above to force it into a code block. Separately, ChatGPT's bullets often come out as •⁠ ⁠ (a bullet followed by an invisible joiner character) instead of a literal - — these won't parse as bullet lists on the site even from inside a code block. Ask it to "use plain - item bullets, no special characters" and check the pasted result before publishing.
"Publish button won't light up." — you're missing the subtitle or the main image. Check both are filled in (Section 3).
"My table isn't rendering as a table." — it needs a header row, then a --- separator row, then data rows, all pipe (|) delimited. A ## [TABLE] heading directly above it helps but a well-formed table is usually detected either way.
Anything not covered here — ask Gary directly rather than guessing; Studio is still evolving and this guide will get updated as it does.
One rule that applies to every post, always: educational and historical framing only. Describe what a strategy or indicator would have done historically — never advice, predictions, or a personal recommendation. The AI prompt already enforces this in its output, but it's worth keeping in mind if you're editing by hand.
